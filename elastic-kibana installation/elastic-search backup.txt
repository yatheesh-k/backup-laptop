To create daily backups of Elasticsearch using snapshots, follow these steps:

1. Set up a Snapshot Repository
First, you need to define a snapshot repository where Elasticsearch will store the backups. This can be done using the repository API, specifying a location where Elasticsearch can store the snapshots.

a. Choose the storage type: Elasticsearch supports several types of storage for snapshots, including:

File system repositories (local disk, NFS, etc.)
Cloud storage repositories (Amazon S3, Azure, Google Cloud, etc.)
Let's go through creating a file system repository, assuming you are using a local disk:

b. Set up the repository (local disk example):

Create a directory where the snapshots will be stored. For example:

bash
Copy
Edit
sudo mkdir -p /mnt/backups/elasticsearch_snapshots
sudo chown elasticsearch:elasticsearch /mnt/backups/elasticsearch_snapshots
Register the repository with Elasticsearch. You can do this by sending a PUT request to the _snapshot endpoint.

Example using the file system repository:

bash
Copy
Edit
curl -X PUT "http://localhost:9200/_snapshot/my_backup" -H 'Content-Type: application/json' -d '{
    "type": "fs",
    "settings": {
        "location": "/mnt/backups/elasticsearch_snapshots",
        "compress": true
    }
}'
"my_backup" is the name of the snapshot repository.
"location" is the directory path where the backups will be stored.
"compress": true enables compression to reduce storage space.
If the request is successful, Elasticsearch will acknowledge that the repository has been created.

2. Create a Snapshot (Backup)
You can create a snapshot of your cluster by using the PUT request to the _snapshot endpoint.

Example:

bash
Copy
Edit
curl -X PUT "http://localhost:9200/_snapshot/my_backup/snapshot_$(date +\%F)" -H 'Content-Type: application/json' -d '{
   "indices": "*",
   "ignore_unavailable": true,
   "include_global_state": false
}'
snapshot_$(date +\%F) will create a snapshot with the current date (e.g., snapshot_2025-02-10).
"indices": "*" means all indices will be included in the snapshot. If you only want specific indices, replace "*" with a comma-separated list of index names.
"ignore_unavailable": true ensures that Elasticsearch doesn’t fail if some indices are unavailable during the snapshot process.
"include_global_state": false excludes the global cluster state, which is typically not necessary for backups.
3. Automate Snapshot Creation with Cron
Now, we’ll automate the snapshot creation process using cron so that it runs daily.

a. Edit the crontab:

Run the following command to edit the crontab for the elasticsearch user (or the user running Elasticsearch):

bash
Copy
Edit
sudo crontab -e -u elasticsearch
b. Add the cron job:

In the crontab editor, add the following line to create a snapshot every day at midnight:

bash
Copy

0 0 * * * curl -X PUT "http://localhost:9200/_snapshot/my_backup/snapshot_$(date +\%F)" -H 'Content-Type: application/json' -d '{"indices": "*", "ignore_unavailable": true, "include_global_state": false}'
This will create a snapshot of all indices at midnight every day, with the snapshot name including the current date.

Explanation:

0 0 * * *: This cron expression means "Run at midnight every day."
curl ...: The command that creates the snapshot, as explained earlier.
4. Verify Snapshot Creation
You can verify that snapshots are being created by checking the snapshot status:

bash

This will list all snapshots stored in the my_backup repository.

5. Restore from Snapshot (Optional)
In case you need to restore from a snapshot, you can do so using the following command:

bash

   "indices": "*"

Replace snapshot_2025-02-10 with the snapshot you want to restore, and you can specify particular indices to restore.

6. Monitor and Manage Snapshot Lifecycle
You may want to add additional steps, like deleting old snapshots to avoid running out of storage. Elasticsearch provides Snapshot Lifecycle Management (SLM) to automate and manage snapshots.

Example: Set up Snapshot Lifecycle Management (Optional)
Create an SLM Policy:
bash

      "include_global_state": false
   },

      "expire_index": "30d"
   }
}'
This policy will:

Create daily snapshots at midnight (schedule).
Use the my_backup repository.
Retain snapshots for 30 days (expire_index).
